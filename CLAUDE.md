## Project Overview

**AutarkTrade** (4.0.0-alpha, formerly *Crypto Trading Journal*) is a **local single-user** trading journal and analysis workstation for **crypto futures** (Bitunix, Bitget, Pionex). It lets users import trades via the exchange APIs (or enter them manually), view dashboards with analytics/charts, keep a diary, manage playbooks, and store screenshots. **Sources without sales clearance (S15):** every source `docs/VERKAUFS-PRUEFUNG.md` rates red/unclear for a SALE runs again behind ONE switch `settings.quellenOhneFreigabe` (Einstellungen › Datenquellen, **default on** — the product is used by its owner); off = the state after S12, for a later sales version. The list of what falls under it is `server/quellen/freigabe.js` (one place, with the review rows). Where the S12 texts below say „removed", that is the switch-off behaviour. Licence: proprietary, `LICENSE` (draft, S10) with `NOTICE.md` and the generated `THIRD-PARTY-NOTICES`; origin of the code base and the proof that no inherited expression is left in `HERKUNFT.md` (check: `node scripts/herkunft-pruefen.mjs`, exits 1 on any unreviewed match — run it before a release and after pasting code from elsewhere; since F3 it checks code lines, the other text files, declared names and token windows for reworded copies, reviewed exceptions with reasons in `scripts/herkunft-akzeptiert.json`). Old routes (`/dashboard`, `/daily`, `/settings/…` …) redirect to the German paths (`/journal`, `/tagesansicht`, `/einstellungen/…`); old journal filter keys in `localStorage` are taken over once by `src/utils/speicherUmzug.js`.

**Rebuild into a product:** done in sessions S1–S13 (completed 19.10.2026; S13 removed live trading — the product does not place orders, see `docs/SPAETER-SCHARFER-HANDEL.md`) — results and open points (lawyer, vendor placeholders, data-provider requests) in `docs/AUFTRAGSSTAND.md`. Rules that still apply: work in your own worktree, `npm run test:self` and the golden master green, then rebase and `git merge --ff-only` onto master; never copy code from the project the fork started from (`HERKUNFT.md`) — the specs describe behaviour — those of S4–S9 (`ansichten.md`, `diagramme.md`, `geruest.md`, `journal-kern.md`, `stil.md`, cited in comments as „… (Beleg)" or „journal-kern.md §…") name the old files' identifiers and therefore live OUTSIDE the repo in `Trading/AutarkTrade-Beleg/clean-room-spezifikationen-2026-10/` with SHA-256 sums (audit A3-20); `docs/spec/f3-*.md` (F3) carry no old names and stay; new dependencies only MIT/ISC/BSD/Apache-2.0; `menu.js`, `router/index.js` and `src/assets/design/tokens.css` are changed only by the session that owns them.

**Key simplifications from the original project:**
- No cloud login (single user, direct to dashboard); API protected by session cookie
- SQLite (or optional PostgreSQL) instead of MongoDB/Parse Server (no Docker needed)
- Bitunix primary; optional Bitget and Pionex brokers (read-only API import or manual entry; no orders are sent; the CSV upload tab was removed in v3.0.0, its code in S3)
- No Stripe payments, no PostHog analytics, no Shepherd tours
- KI-Agent: AI reports/chat (Ollama, Anthropic, OpenAI, Gemini, Mistral, xAI, Qwen, Perplexity, Moonshot, Z.ai, OpenRouter, an own OpenAI-compatible provider and a second OpenAI-compatible endpoint; registry `server/ai-models.js`), every output labelled as AI-generated

## Tech Stack

- **Frontend**: Vue 3 (Composition API with `<script setup>`), Vue Router, Vite; state via `ref()`-Exporte in `src/stores/` (kein Pinia)
- **Backend**: Express.js with Knex (SQLite default, optional PostgreSQL)
- **Market data**: public exchange data only through `server/marktdaten/` (customer-chosen source Binance/Bitget/off, see Architecture); third-party sources that need it run only with the customer's key (`server/quellen/`)
- **Charts**: Apache ECharts; the chart workspace (`/chart`) uses Lightweight Charts 5 (TradingView, Apache-2.0 — the attribution logo must stay on)
- **Styling**: own design system (`src/assets/design/`: `tokens.css`, `basis.css`, `hilfen.css`, `kacheln.css`, `journal.css`, `quill.css`, `rahmen.css`; building blocks in `src/components/basis/`, own SVG icon set `Symbol.vue`). No Bootstrap, no Font Awesome, no Unicons, no CDN (removed in S9; `src/utils/__selftest-ohne-bootstrap.mjs` keeps it that way)
- **Other key libs**: dayjs (dates/timezones), PapaParse (only the Databento OHLCV CSV in `utils/journal/import.js`), Quill (rich text, Playbook and Incoming only, bundled via npm), axios. No lodash (removed in F3; it is only a transitive dependency of knex). Screenshot annotation is our own (`src/utils/bildmarkierung.js` + `components/bildmarkierung/BildMarkierung.vue`, state `maState` v2 in relative coordinates; stored markerjs2 states are read and migrated on save)

## Architecture

### Server

- **`index.mjs`** — Entry point: Express server + DB init (Knex) + API routes. Session cookie set for all non-API requests; all `/api/*` require valid session. In dev mode (`NODE_ENV=dev`), proxies non-API requests to Vite dev server on port 39482. In production, serves static files from `dist/`. Default bind: `127.0.0.1` (override with `AT_HOST`).
- **`server/database.js`** — Knex setup: **`initDb()`** / **`getKnex()`**. Schema and migrations in code. Default: SQLite (**`autarktrade.db`** in project root, WAL mode; an existing `tradenote.db` is kept in use when it is the only file). Optional PostgreSQL via **`server/db-config.js`** and `db-config.json`. Tables: settings, trades, diaries, screenshots, playbooks, satisfactions, tags, notes, excursions, bitunix_config, bitget_config, incoming_positions, ai_reports, ai_report_messages, market_snapshots (daily snapshots of values without free history, e.g. BTC dominance), radar_fetch_state (claims for periodic tasks), calendar_events, live_sessions (one row per trading session in the live-trading window: plan, notes, verdict, frozen trade snapshot), hype_projekt (24 h cache of Hype-Radar project checks), hype_frueh (tokens watched by the Hype-Radar early phase, with snapshot history), hype_gedaechtnis (first seen / first flagged per contract), hype_smart_stand + hype_smart_kaeufe (smart-money wallets), hype_boersen_stand + hype_listungen_neu (exchange watcher), chart_layouts + chart_watchlists + chart_zeichnungen + chart_alarme (chart workspace, v26), chart_vorlagen (indicator templates, v27), strategy_* (simulated strategy instances; `strategy_positions.ausgelagert` marks pre-S13 live rows, v29), etc. `SCHEMA_VERSION` at the top guards against an older code stand writing against a newer schema — it only warns, it never aborts.
- **`server/auth.js`** — Session cookie (`at_session`) for API auth; token generated at startup. Since F2 (20.10.2026, audit A2): `istLoopbackHost` only real 127/8 literals, `isLocalRequest` (in `update-api.js`) also rejects a foreign `Origin`/`Sec-Fetch-Site`, `/api/auth/reset` needs JSON and bumps the session generation, `X-Forwarded-For` counts only from `AT_TRUSTED_PROXY` (default `caddy,autarktrade-caddy`) plus a global brake of 60 failures/min, async scrypt with 2 parallel hashes, the first password from the network needs the setup code from the log (`meldeEinrichtungsCode`), min. 10 characters, `POST /api/auth/ueberall-abmelden`. The HMAC purpose string `tn_session_v1` stays unchanged on purpose (a new one would log out every device and break the shell tokens of the diagnosis scripts).
- **`server/umgebung.js`** — Environment variables: `umgebung('X')` reads `AT_X`, falling back to the pre-rename `CTJ_X` (old compose files and NAS containers keep working); `umgebungAn('X')` for `=== '1'` switches. Read at call time, not at load. Security switches (`SICHERHEITS_SCHALTER`: ALLOW_INSECURE, RESET_AUTH, TRUST_PROXY, TRUSTED_PROXY, ALLOWED_HOSTS) do not fall back once `AT_X` is set at all, even empty; active `CTJ_` switches are logged at start.
- **`server/geheimnisse.js`** — The ONE list of where secrets live (F2): encrypted settings columns (AI keys derived from the registry), other secret fields, target fields (AI URLs, SMTP) and access fields kept on backup import, exchange config tables. Used by the settings redaction, backup, `reencrypt-keys.mjs` and the start migration; `server/__selftest-f2-sicherheit.mjs` fails when a column with a secret-looking name is missing.
- **`server/crypto.js`** — AES-GCM for stored keys. Without `AT_SECRET` (native installs) a random secret is created once in `.at-secret` (0600, `AT_SECRET_FILE`), the old machine-seed key stays readable and `migriereAltSchluessel` re-encrypts on start (also plaintext → encrypted, `[REDACTED]` → empty). Production without `AT_SECRET` still aborts. Masks show only the last 4 characters.
- **`server/testbetrieb.js`** — Test mode `AT_TESTBETRIEB=1` for the V2 test instance, which runs against a COPY of the live DB (real exchange keys, open positions, notification channels) and in its own DB is the only bidder for every leadership claim. `starteTakte([[name, fn], …])` starts the background takts in `index.mjs` — or none of them; engine, recorder, the calendar/snapshot/ETF timers also ask `istTestbetrieb()`. `versandGesperrt()` is checked at the transport (`sendeMail`, `melde`, hype `post`), not at every caller, so neither mail nor push leaves. Buttons keep working (a human who presses pays knowingly). `GET /api/system/modus` → `{testbetrieb}` lets the browser switch off its own paid automation (Handelslage); there is no visible banner. `server/__selftest-testbetrieb.mjs` also fails if a `start…Takt()` in `index.mjs` bypasses `starteTakte`.
- **`server/api-routes.js`** — Generic REST CRUD (`GET/POST/PUT/DELETE /api/db/{table}`) using Knex; table/column whitelist; settings and bitunix_config endpoints (bitunix_config response omits secretKey).
- **`server/bitunix-api.js`** — Bitunix API client (SHA256 double-hash auth); encrypt/decrypt for API keys; proxy endpoints for positions.
- **`server/bitget-api.js`** — Bitget API (HMAC-SHA256); encrypt/decrypt for keys.
- **`server/marktdaten/`** — Market-data abstraction (S12, sales review measure 1): no function talks to an exchange's public market data directly any more. The customer picks the source under Einstellungen › Datenquellen (`settings.marktdatenQuelle`: `binance` | `bitget` | `aus`) and is told that checking the exchange's terms is their responsibility — no exchange explicitly allows its public data in a sold product, Binance's terms are unclear. Callers ask for a CAPABILITY, never a name: `kerzen`, `spot`, `ticker`, `orderbuch`, `funding`, `symbole` (Binance + Bitget), `oiHistorie`, `takerVolumen`, `longShort`, `liquidationen`, `streams`, `listungen` (Binance only). `index.js` has the common calls (`kerzen`, `preis(e)`, `ticker24h` in one shape, `orderbuch`, `funding(Verlauf)`, `symbole`) and for Binance-only paths `binanceRest/binanceHole/binanceWs(faehigkeit, …)`; a missing capability throws `MarktdatenAus`, routes answer HTTP 200 `{aus: true, grund: 'marktdaten', …}` via `sendeWennAus`, takts skip and log once. **Binance URLs live only in `binance.js`** (the selftest greps the code base) — including, since S15, the undocumented bapi endpoints `bapiKlammern()` (maintenance-margin brackets for `margin-rates.js`, Bybit as fallback, switch id `binanceBrackets`) and `bapiAlphaListe()` (Binance Alpha for the exchange watcher), which do not depend on the chosen source and run only with `quellenOhneFreigabe` on; the browser gets its stream roots from `GET /api/marktdaten/quelle`. `bitget.js` was verified against the live API 19.10.2026: `candles` reaches only ~90 daily candles back, older ones page backwards via `history-candles` (200 per page, before `endTime`); `change24h` is a fraction; tokenised stocks/commodities are flagged `isRwa: "YES"` (376 of 842 contracts) and filtered out like Binance's `underlyingType !== 'COIN'`. The Binance weight brake (`binance-takt.js`) applies only with Binance chosen. Selftest `server/marktdaten/__selftest-marktdaten.mjs`.
- **`server/quellen/`** — Sources that need a reason to be off (S12). `freigabe.js` (S15): `QUELLEN_OHNE_FREIGABE` (id → name, review rows, what), `quelleErlaubt(id)`/`quelleErlaubtSofort(id)`/`fordereQuelle(id)` (throws `QuelleAus(name, 'ohneFreigabe')`), an unknown id throws; switch read with a 30 s cache, unknown = on; `GET/PUT /api/quellen/ohne-freigabe`, browser `src/utils/quellenFreigabe.js`; selftest `server/quellen/__selftest-freigabe.mjs` (also: every id the code asks for is in the list, every row exists in the review). Migration `server/migrationen/s15.js`: column (default on), with the switch on every start re-enables Telegram news sources S12 marked off, once (`s15Migriert`) calendar countries `USD,EUR` → `USD,JPY` and maintenance margin `bybit` → `binance`; `s12.js` skips its switch-off steps while the switch is on. `aus.js`: `QuelleAus(quelle, grund)` with `schluesselFehlt` | `entfernt` | `aus` | `ohneFreigabe`, plus `istAus/ausAntwort/sendeWennAus` (also covering `MarktdatenAus`); the browser shows `src/components/quellen/QuelleAus.vue` (link to Einstellungen › Datenquellen via `localStorage.settingsBereich`). `coingecko.js`: own key first; without one and with the switch on the public endpoint (`tarif: 'oeffentlich'`, `/onchain/…` paths go to `api.geckoterminal.com/api/v2`; `hatSchluessel()` = usable, `hatEigenenSchluessel()` = own key); switch off: CoinGecko ONLY with the customer's key (`settings.hypeKeyCoingecko`, tier `settings.coingeckoTarif` demo/pro → api./pro-api.coingecko.com with the matching header); GeckoTerminal data runs through the CoinGecko `/onchain/…` endpoints with the same key. `routen.js`: `GET /api/quellen`, `PUT /api/quellen/coingecko`, `POST /api/quellen/coingecko/test`. UI: `src/views/einstellungen/EinstellungenDatenquellen.vue`. Migrations of S12 (settings carried over idempotently on every start): `server/migrationen/s12*.js`.
- **`server/binance-api.js`** — Proxy routes `/api/binance/*` (klines, depth, exchange-info, leverage-map), now through `server/marktdaten/`; `/depth` and `/leverage-map` need Binance.
- **`server/ollama-api.js`** — AI: Ollama, OpenAI, Anthropic, Gemini, DeepSeek (reports + chat).
- **`server/ai-agent.js`** — Autonomous KI-Agent with tool use / function calling. Supports Anthropic (native), OpenAI/DeepSeek (native), Gemini (native), Ollama (prompt-based fallback). Agent loop runs via SSE streaming; max 10 iterations; concurrency-guarded (one run at a time).
- **`server/ai-agent-tools.js`** — Tool definitions and `executeTool()` for the agent loop (DB queries, trade analysis, etc.). Also `query_app_help` (answers about the software itself, sourced from `server/app-hilfe.js`) and `query_marktradar` (current Marktradar tile readings via `sammleKacheln`/`baueZeilen` — same cached `hole*` functions the tiles use).
- **`server/app-hilfe.js`** — Built-in German usage documentation of the app, one section per topic. Single source the KI-Agent may quote about the software; describes the UI, not the implementation.
- **`server/flux-api.js`** — Share Card API: generates stylized trade share images using FLUX.2 (Black Forest Labs) AI backgrounds + SVG overlay. Returns background (`hintergrund`, data URL) and overlay (SVG) separately; the BROWSER composes them (`src/utils/shareCardBild.js`, canvas, 1080² cover). `sharp` was removed on 19.10.2026 (LGPL via libvips, decision in `NOTICE.md`). Admin: `/api/flux/*`.
- **`server/esp32-api.js`** — Read-only endpoint for ESP32-2432S028 (CYD) hardware display. Auth via static API key in `X-ESP32-Key` header (key stored encrypted in `settings.esp32ApiKey`). `/api/esp32/display` is public (no session); admin routes behind session.
- **`server/backup-api.js`** — JSON export/import of all DB tables. Redacts sensitive keys (AI keys, etc.) on export. Handles import order to respect FK constraints.
- **`server/update-api.js`** — Checks the PRIVATE package source (`GET /api/update/check`: GitHub releases of `Mouses007/AutarkTrade`) and performs the one-click update (`POST /api/update/install`: `git fetch --depth 1 --no-tags <url> master` + reset + `macheFlach` + npm install, or `docker pull ghcr.io/mouses007/autarktrade` with `X-Registry-Auth`). Access from `AT_UPDATE_TOKEN`/`AT_UPDATE_BENUTZER` or the `zugang` field of the licence key, passed to git via `GIT_CONFIG_*` (never on the command line, never in `.git/config`). - **`server/radar-ergebnisse.js`** / **`radar-guete.js`** — outcome tracking (audit R-06). ### Key Backend Patterns

**`objectId` mapping**: SQLite uses `id` (auto-increment), but the frontend expects `objectId` (legacy from Parse). `api-routes.js` maps `id` → `objectId` in all responses and `objectId` → `id` in incoming requests.

**JSON columns**: Certain columns (e.g., `trades.executions`, `trades.blotter`, `trades.pAndL`, `screenshots.maState`) are stored as TEXT in SQLite. `api-routes.js` auto-stringifies on write and auto-parses on read via the `JSON_COLUMNS` config object.

**Boolean conversion**: JavaScript `true`/`false` ↔ SQLite `1`/`0`, handled in api-routes.js.

### Frontend (`src/`)

**Import alias**: `@` resolves to `src/` (configured in `vite.config.js`).

**Layout system**: `App.vue` wraps every route with `meta.rahmen` in `layouts/Rahmen.vue` (Kopfleiste, side menu `components/rahmen/Seitenmenue.vue` with `MenueJournalKopf`/`MenueFuss`, title bar `rahmen/Titelzeile.vue`, content). On desktop the Titelzeile sits INSIDE the Kopfleiste on the right (`in-kopf`, together with settings and logout; below 1500 px the modes show icons only) — only phones keep it as its own row, because there its title opens the side menu. Routes in `src/router/routen.js` (table, all lazy-loaded, catch-all → `/`), guards in `src/router/index.js`; both rebuilt clean-room in S9 from `geruest.md (Beleg)`. Menu entries and their `symbol` come from `src/config/menu.js`. Settings live under `/einstellungen/:bereich?` (old `/settings/…` redirects) (`EINSTELLUNGS_BEREICHE` in `routen.js`; unknown → allgemein): `views/Einstellungen.vue` is a shell with tabs, areas and sections under `views/einstellungen/` (shared pieces `gemeinsam/Abschnitt|Feld|Schalter.vue` and composables).

**State management** (`src/stores/app/*` — rahmen, laden, einstellungen — and `src/stores/journal/*` — filter, auswertung, import, tagebuch, kalender, bilder, offenePositionen; the bundles `stores/{ui,filters,trades,settings}.js` re-export them): Uses Vue `ref()` and `reactive()` exports directly — **not Pinia stores**. Components import and mutate these directly. Filter state (selected tags, positions, date ranges, etc.) is persisted to `localStorage`.

**`appEinstellungen.value`**: Holds app settings loaded from the SQLite `settings` table via `dbGetSettings()`. This is not a user object — it's the single-user settings record.

Sessions can be **archived** (`archiviert` column) instead of deleted — the discipline tally deliberately keeps counting archived ones, otherwise the number could be improved by tidying up. A session is a **period, not a market**: the symbol may change during it, every switch lands in the log, and `symbol` follows the last one picked (that is what the replay button needs).
- `LiveAuswertung.vue` — Four questions about the sessions, building on each other: do I keep my plan and am I improving, does the plan help at all, at which times do I trade well, does it turn with duration or trade count. Computation lives in `src/utils/sitzungStatistik.js` (pure, no Vue, no network — selftest alongside it); the view only draws. Groups below `MIN_GRUPPE` carry `duenn: true` and are greyed out: three sessions on a Tuesday are noise, not a finding. Same approach as `KachelRegime.vue`.
- `Nachrichten.vue` — News page (`/nachrichten`): AI briefing at the top styled as a newspaper article (serif headline, chapter per topic, two-column body, drop cap), with an archive browser (open/delete old reports, two-click delete) and compact 3-column point tiles below; then economic calendar with adjustable range/impact/countries, and the raw posts with thumbnails. YouTube posts appear in the list with a "Video" badge and their collapsible bullet-point summary (they also feed the briefing).

- `HypeRadar.vue` / `CoinRadar.vue` — The two pages of the `research` mode (`/hype-radar`, `/coin-radar`; the Hype-Radar has four side-menu views on one route — overview, `fruehphase` rendered by `src/components/hype/FruehphaseAnsicht.vue`, `boersen` by `BoersenAnsicht.vue`, and `berichte`; `src/components/hype/ProjektPruefung.vue` shows a project check in all three), siblings with opposite questions: "what is new out there" vs. "what can be traded today". Same shape, same star, same expandable sub-scores; phone gets cards instead of tables. The former in-page tabs are gone: each view is a **side-menu entry** on a shared route (`/hype-radar` + `/hype-radar/berichte`, `/coin-radar` + `/coin-radar/verlauf`) — one route record per page, so switching does not remount and a running scan keeps its SSE stream. Settings are no longer a tab but a **gear panel with a one-line summary**, the same pattern as `Nachrichten.vue`. The star feeds one shared `hype_favoriten` list — `quelle` decides which watchdog data path applies. `CoinRadar.vue` shows the **rank correlation among the headline figures**, in words as well as a number ("Rangfolge ist grösstenteils Rauschen"): a ranking that hides its own predictive power is more dangerous than none. The gate view switches to a **different column set** (reason, turnover, spread, depth) rather than printing zeros — for a rejected coin no metrics were ever computed. Note: the side menu renders per-mode groups (`research` = `HYPE-RADAR` + `COIN-RADAR`) and highlights by **path, not `seitenId`** — two entries share one route name, so `seitenId` would light up both. `menuKey`/`menuIcon` in `menu.js` let a menu entry read "Übersicht" while the page header still says "Hype-Radar".
- `Incoming.vue` — Live open positions from Bitunix API
- `TradeImport.vue` — Manual single-trade entry + API import (no CSV import; removed from the UI in v3.0.0 and from the code in S3)

### Key Components

- `InfoTipp.vue` — the one way to attach an inline explanation to a single element: a small "i" that shows text on hover (tap on phones), globally switchable via the `erweiterteInfos` setting (default on, mirrored to `localStorage` so nothing flashes before settings load). Deliberately declarative (no imperative tooltip library): an imperative instance is orphaned by a `v-if`, and help text must work offline. Positioning is `Teleport to="body"` + fixed coords from `getBoundingClientRect()`, the same pattern and the same reason as `PageInfo.vue`/`RadarOverlay.vue` (tile heads clip overflow). `te()` before `t()` is mandatory: a missing key renders **nothing** rather than the raw key — the bug that made `info.coinRadar.caveat` show up literally for months. Boundary: `title=` says what a control **is**, `InfoTipp` says what a number **means**, so the existing `title=` attributes on bare icon buttons stay. Tile-level texts attach through `infoKey` on the registry entries, derived in `kachel-registry.js` as `<raum>.title` → `<raum>.info` (two Live-Trading tiles hang on `nav.liquidity`/`nav.liquidations` and carry an explicit `infoKey`) — ~29 texts cover their placements across Marktradar and Live-Trading.
- `ShareCardModal.vue` — Trade share card generator (FLUX.2 AI image + SVG overlay via `flux-api.js`)
- `TradeEvalPopup.vue` — Trade evaluation/rating popup (SL/TP, RRR, etc.)
- `journal/FilterLeiste.vue` — Global filter panel in the side menu (tags, date range, position type); state in `stores/journal/filter.js`

### Environment Variables

All variables are read through `server/umgebung.js`: `AT_X`, falling back to the former `CTJ_X`.

- `AT_PORT` — Server port (default 8080; also accepts `PORT`)
- `AT_HOST` — Bind address (default 127.0.0.1; use 0.0.0.0 for network access)
- `AT_SECRET` — Secret for session token / crypto key derivation (required in production)
- `NODE_ENV=dev` — Enable Vite dev server with HMR
- `AT_NO_ENGINE=1` / `AT_NO_RECORDER=1` — keep this process out of the strategy engine (simulation only since S13) or the live recorder. Both use DB leadership claims across processes sharing one PostgreSQL; a local test container should run with `AT_NO_ENGINE=1 AT_NO_RECORDER=1`, otherwise it can win the recorder lead after a NAS restart and the NAS's in-memory liquidation ticker stays empty.
- `AT_TRUSTED_PROXY` — proxies whose `X-Forwarded-For` the login counter believes (with `AT_TRUST_PROXY=1`; default `caddy,autarktrade-caddy`)
- `AT_SECRET_FILE` — path of the generated secret of native installs (default `.at-secret` in the project root)
- `AT_TESTBETRIEB=1` — test mode (see `server/testbetrieb.js`): no takts, engine, recorder, mail or push; no banner — the operator knows (removed 19.10.2026).
- V2 test container: `scripts/v2-container.sh` builds `autarktrade:v2-test` and runs `autarktrade-v2` on port **8091** against the NAS database `autarktrade` (a copy of the live DB, made 19.10.2026) with `AT_TESTBETRIEB=1 AT_NO_ENGINE=1 AT_NO_RECORDER=1`; credentials in the untracked `scripts/.v2-container.env`. The script refuses `DB_NAME=tradejournal`.

No `.env` files — runtime config stored in DB (settings table) and localStorage. Optional DB: `db-config.json` for PostgreSQL.

### Bitunix / Bitget Integration

**CSV Import**: none. Removed from the UI in v3.0.0 and from the code in S3 (19.10.2026); imports run via API (or manual entry) only. The CSV *export* of filtered trades on the dashboard is unaffected.

**API Import**: Configure API Key + Secret (Bitunix) or API Key + Secret + Passphrase (Bitget) in Settings. Keys are encrypted at rest (`server/crypto.js`). Server-side proxies (`/api/bitunix/*`, `/api/bitget/*`) fetch positions; Bitunix uses SHA256 double-hash auth.
